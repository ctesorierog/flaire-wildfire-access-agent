## 2. Buildings (D2)

Source: `raw/GFA_INSPIRE_BU.gpkg` (B5M / DFG INSPIRE Buildings, single layer `GFA_INSPIRE_BU`, Polygon, EPSG:25830, layer metadata
`DBF_DATE_LAST_UPDATE = 2026-08-08`). 124,140 raw rows for all of Gipuzkoa.

### Province-wide profile (raw rows)
- `CURRENTUSE` is **not a code list but a composite string** `"<code> <pct>%; <code> <pct>%"` (6,069 distinct strings; shares sum to ≤100 %).
  Codes found (token counts): `collectiveResidence` 30,568, `individualResidence` 23,222, `commerceAndServices` 21,761, `agriculture` 7,305, `industrial` 5,285. NULL: 62,098 rows (50 %).
- NULL use = B5M cartographic buildings without a cadastral unit: 55,874 of them have only a B5M map link in `URL_CADAST`
  (no catastro link). They are mostly small structures (huts, sheds, annexes, tanks), but not only (see "unknown use" below).
- `DWELLINGS`: NULL 61,298, 0 = 9,048, >0 = 53,794 (max 159). Every building with a use has a dwellings value;
  NULL dwellings ⇔ NULL use, except 800 null-use rows with an explicit 0 (kept as 0).
- IDs: `INSPIREID` = `ES.GFA.BU.<LOCALID>` for 100 % of rows (True), so both are the same key
  (schema says `building_id` = localId; we store `building_id` = INSPIREID and `localid` separately — equivalent).
  **114 INSPIREIDs repeat on 458 rows** (2–8 copies). All copies have identical geometry and identical
  core attributes (use, dwellings, floors, value, address); only `BUILDING_N`, `URL_CADAST`, `URL_PARCEL` and `ENDCONSTRU` differ → export fan-out
  (one row per name / cadastral reference), not separate buildings.
- Invalid geometries: 43 self-intersections province-wide, **0 inside the Tolosaldea area**.

### BuildingPart check
The file has one layer (['GFA_INSPIRE_BU']), every id has the `ES.GFA.BU` (Building) prefix
({'ES.GFA.BU': 124140}), and there is no BuildingPart feature type. Inside Tolosaldea, 3,501
footprint pairs touch/intersect, only 14 overlap by >1 m², and 10 are ≥99 % contained in another footprint
(`overlapping_footprints_gt50pct.csv`): structures inside the San Blas and Bidania cemeteries and IES Orixe, plus 2 residential buildings inside a
598 m² unknown-use block with 0 dwellings. **No residential-in-residential nesting, so the layer does not double count.**

### Cleaning rules (in order)
1. **R-DUP-ID**: one row per INSPIREID. Kept the first row by LOCALID; `building_name` = all distinct `BUILDING_N` joined by " | ";
   `end_construction` = latest of the copies (they differ for 21 ids province-wide → `endconstru_multi` = true);
   `n_source_rows` records how many raw rows were merged. Province-wide 344 rows dropped; in Tolosaldea see the table.
2. **Geometry**: `make_valid` on invalid footprints (none needed in Tolosaldea; `geom_fixed` flag kept). Everything written as MultiPolygon.
3. **Municipality**: `representative_point()` of the footprint (always inside it) within the OSM municipality (predicate *within*). One municipality
   per building; points in more than one municipality: 0 (tie rule would be lowest INE). Buildings that cross the boundary but whose rep point is outside:
   5 → excluded ({'Errezil': 3, 'Gaintza': 1, 'Andoain': 1}).
4. **R-DUP-GEOM**: different INSPIREIDs with an identical normalised footprint → keep lowest LOCALID. Tolosaldea: 1 group, 1 dropped
   (no use, no dwellings). Province-wide there are 6 such groups, all null-use B5M structures.
5. **Residential rule** (`residential_flag`):
   - `residential` = `CURRENTUSE` contains **`collectiveResidence` or `individualResidence`** at any share (>0 %)
   - `unknown` = `CURRENTUSE` is NULL
   - `non_residential` = use present, only `commerceAndServices` / `agriculture` / `industrial`
   The plan's fallback ("dwellings > 0 when use is missing") never fires: no null-use building has dwellings > 0.
   Sensitivity: 3,660 of 5,291 residential buildings have a residential share ≥50 % (stricter "dominant use" rule).
   `residential_share_pct` and `dominant_use` are stored so the team can switch rules.
6. **Dwellings**: copied as published; NULL stays NULL (never 0), genuine 0 kept.

## 4. Building–vegetation proximity

`dist_veg_m` = planar distance (EPSG:25830) from the **building footprint** to the nearest forest/scrub_heath polygon (0 = touches or lies inside).
Computed with an STRtree nearest query on fuel polygons split on a 1 km grid (same union, faster). Validated against brute-force distance to the fuel union on
300 random buildings: max difference 0.005 m. NULL distances: 0. `near_veg_100` = `dist_veg_m` ≤ 100 (`veg_rule_m` = 100).
Note: the schema comment says "rep point within this distance"; we use the footprint (rep-point distance is ≥ footprint distance). **Team to confirm.**
